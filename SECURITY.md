# Security Policy

Do not put credentials, tokens, private keys, private repository content, customer data, or sensitive machine paths in issues, pull requests, examples, fixtures, or skill files.

For a security-sensitive vulnerability, use GitHub's private vulnerability reporting flow for this repository if it is available. If that option is unavailable, open a minimal public issue requesting a private contact channel without including exploit details or sensitive data.

The repository validator catches several obvious secret/path patterns, but automated scanning is not a substitute for review.
